STUDENT CRUD MICROSERVICE REFERENCE
Node.js + Express + Docker + Kubernetes
Updated: 13 October 2026

============================================================
1. PROJECT FILES
============================================================

student-microservice/
    server.js
    package.json
    package-lock.json
    Dockerfile
    deployment.yml (optional)
    service.yml (optional)

server.js implements:
- GET /                -> status/message
- GET /students        -> list students
- GET /students/:id    -> get one student
- POST /students       -> add a student
- PUT /students/:id    -> update a student
- DELETE /students/:id -> delete a student

The current API stores data in an in-memory array:
- Data resets when the server restarts.
- Each Kubernetes replica has its own separate array.
- For shared persistent data, use a database.

============================================================
2. package.json
============================================================

Create the file and install Express:
    npm init -y
    npm install express

Ensure package.json has:
    "scripts": {
      "start": "node server.js"
    }

package.json records dependencies and project scripts.
package-lock.json is generated by npm install.

============================================================
3. DOCKERFILE
============================================================

Use a file named exactly Dockerfile (no .txt extension):

    FROM node:24-alpine
    WORKDIR /app
    COPY package*.json ./
    RUN npm install --omit=dev
    COPY server.js ./
    EXPOSE 3000
    CMD ["npm", "start"]

Build the image:
    docker build -t student-microservice .

Run a container:
    docker run -d --name student-api -p 3000:3000 student-microservice

Check:
    docker ps
    docker logs student-api

Local Docker URL:
    http://localhost:3000/

If host port 3000 is occupied, stop the local server or use:
    docker run -d --name student-api -p 3001:3000 student-microservice
Then use http://localhost:3001/

============================================================
4. KUBERNETES DEPLOYMENT USING COMMANDS
============================================================

Create a Deployment with two replicas:
    kubectl create deployment student-deployment --image=student-microservice:latest --replicas=2

Check:
    kubectl get deployments
    kubectl get pods

Expose the Deployment as a Service:
    kubectl expose deployment student-deployment --type=NodePort --port=3000

Check:
    kubectl get services

Forward the Service port to your local computer:
    kubectl port-forward service/student-deployment 8082:3000

Keep port-forward running while testing.
Open:
    http://localhost:8082/

Run port-forward in a separate Windows CMD window:
    start "Student Port Forward" cmd /k "kubectl port-forward service/student-deployment 8082:3000"

Ctrl+C stops only port-forward, not the Deployment, Pods or Service.

IMPORTANT IMAGE NOTE:
The Kubernetes cluster was created with Docker Desktop's kind-based setup.
A Docker image built on the host may not automatically be available inside a kind node.
If Pods show ImagePullBackOff or ErrImagePull:
    kubectl describe pod POD_NAME
Check the image name/tag and make the image available to the cluster (for example, load it into kind or push it to a registry).

============================================================
6. WHAT EACH FILE/COMPONENT DOES
============================================================

server.js
- Contains the Student API logic and CRUD routes.

package.json
- Lists dependencies and npm scripts.

Dockerfile
- Defines how to build the container image.

Docker image
- Packaged application and runtime dependencies.

Deployment
- Keeps the requested number of Pods running.

Service
- Provides a stable network endpoint to reach matching Pods.

Port-forward
- Temporary connection from localhost to a Kubernetes Service.
